## このチャプターで何をするか

これまでChapter 2〜5で手動で実行してきた一連の処理を、
「1コールで実行できる関数」にまとめます。

> 💡 **ストアドプロシージャとは？**
> Snowflake内に保存できる「手続き（プロシージャ）」です。
> 複数のSQLをひとまとめにして名前をつけて登録しておくことで、
> `CALL プロシージャ名()` という1コールで実行できます。
>
> **やらないと？** 毎回4〜5個のSQLを手動で順番通りに実行する必要があります。
> 順番を間違えたり、途中で止まったりするリスクがあります。
> **やると？** 1コールで全処理が完結し、次のChapterのTaskによる自動実行にも対応できます。

## 6-1 Bronze ロードのストアドプロシージャ

> 💡 **`EXECUTE AS CALLER` とは？**
> プロシージャを「呼び出したユーザーの権限」で実行するオプションです。
> デフォルトは `EXECUTE AS OWNER`（プロシージャ作成者の権限）ですが、
> `CALLER` にすることで呼び出しユーザーの権限チェックが働きます。
>
> **やらないと？** OWNER権限が強すぎる場合、意図しないオブジェクト操作が行われるリスクがあります。
> **やると？** 権限管理が呼び出しユーザーに委ねられ、セキュリティが向上します。

> 💡 **JavaScript で書く理由**
> Snowflakeのストアドプロシージャはいくつかの言語（JavaScript・Python・Snowflake Scripting）で書けます。
> ここではSnowflakeの歴史的にも広く使われているJavaScriptを使います。
> `snowflake.execute()` でSQLを実行し、エラーは `try/catch` で捕捉します。

```sql
CREATE OR REPLACE PROCEDURE SENSOR_LAB.BRONZE.SP_LOAD_FROM_STAGE(
    stage_name   VARCHAR,   -- アップロード先ステージ名（引数として受け取る）
    file_pattern VARCHAR    -- ロード対象ファイルの正規表現パターン
)
RETURNS VARCHAR             -- 処理結果のメッセージを文字列で返す
LANGUAGE JAVASCRIPT         -- JavaScriptで記述
EXECUTE AS CALLER           -- 呼び出しユーザーの権限で実行
AS $$
    var result_msg = "";
    try {
        // 動的SQLを組み立て（引数をSQL文字列に埋め込む）
        var sql = `
            COPY INTO SENSOR_LAB.BRONZE.RAW_SENSOR
            (timestamp, sensor_id, location, temperature_c, humidity_pct, battery_pct, status, _source_file)
            FROM (
                SELECT $1,$2,$3,$4,$5,$6,$7, METADATA$FILENAME
                FROM @SENSOR_LAB.BRONZE.` + STAGE_NAME + `
            )
            FILE_FORMAT = (FORMAT_NAME = 'SENSOR_LAB.BRONZE.CSV_FORMAT')
            PATTERN = '` + FILE_PATTERN + `'
            ON_ERROR = 'CONTINUE'
        `;
        var stmt = snowflake.execute({sqlText: sql});  // SQLを実行
        result_msg = "Bronze load completed.";
    } catch(err) {
        // エラーが発生してもプロシージャ自体は終了し、エラーメッセージを返す
        result_msg = "ERROR: " + err.message;
    }
    return result_msg;  // 呼び出し元に結果メッセージを返す
$$;

-- 実行テスト
CALL SENSOR_LAB.BRONZE.SP_LOAD_FROM_STAGE('BRONZE_STAGE', '.*sensor_.*\\.csv');
```

## 6-2 Silver層変換のストアドプロシージャ

> 💡 **`TRUNCATE + INSERT` パターンとは？**
> テーブルを一度空にしてから全件INSERTするパターンです。
>
> | パターン | 動作 | 使いどころ |
> |---|---|---|
> | `DELETE + INSERT` | 条件に合う行を削除してINSERT | 差分更新が必要な場合 |
> | **`TRUNCATE + INSERT`** | 全件削除してから全件INSERT | 全データを再構築する場合（今回） |
> | `MERGE` | 差分だけ更新・挿入・削除 | 増分更新が必要な場合 |
>
> Silverは「Bronzeの全データをクレンジングしたもの」なので、
> Bronzeが変わったら全件作り直すのが最もシンプルで正確です。
>
> **やらないと？** 前回のデータが残ったまま追加されてしまい、重複が発生します。
> **やると？** 常に最新のBronzeデータからクリーンなSilverが生成されます。

```sql
CREATE OR REPLACE PROCEDURE SENSOR_LAB.SILVER.SP_TRANSFORM_TO_SILVER()
RETURNS VARCHAR
LANGUAGE JAVASCRIPT
EXECUTE AS CALLER
AS $$
    try {
        // Silver テーブルを一旦空にする（全件削除 ≒ DROP+CREATE より高速）
        snowflake.execute({sqlText: "TRUNCATE TABLE SENSOR_LAB.SILVER.SENSOR_CLEAN"});

        // Bronze から Silver へのクレンジング INSERT
        var sql = `
            INSERT INTO SENSOR_LAB.SILVER.SENSOR_CLEAN
            SELECT
                sensor_id, location, timestamp,
                DATE(timestamp), HOUR(timestamp),
                -- 気温: 異常範囲はNULL
                CASE WHEN temperature_c < -50 OR temperature_c > 80 THEN NULL
                     ELSE temperature_c END,
                -- 湿度: 範囲外は境界値にクランプ
                CASE WHEN humidity_pct < 0 THEN 0
                     WHEN humidity_pct > 100 THEN 100
                     ELSE humidity_pct END,
                battery_pct, status,
                (temperature_c < -50 OR temperature_c > 80),  -- is_anomaly フラグ
                CURRENT_TIMESTAMP(), _source_file
            FROM SENSOR_LAB.BRONZE.RAW_SENSOR
            QUALIFY ROW_NUMBER() OVER (
                PARTITION BY sensor_id, timestamp ORDER BY _loaded_at DESC
            ) = 1  -- 重複排除: 最新ロード分のみ残す
        `;
        snowflake.execute({sqlText: sql});
        return "Silver transform completed.";
    } catch(err) {
        return "ERROR: " + err.message;
    }
$$;
```

## 6-3 Gold層集計のストアドプロシージャ

```sql
CREATE OR REPLACE PROCEDURE SENSOR_LAB.GOLD.SP_AGGREGATE_TO_GOLD()
RETURNS VARCHAR
LANGUAGE JAVASCRIPT
EXECUTE AS CALLER
AS $$
    try {
        // Gold テーブルを全件クリア（Silver が更新されたら Gold も再構築）
        snowflake.execute({sqlText: "TRUNCATE TABLE SENSOR_LAB.GOLD.HOURLY_STATS"});
        snowflake.execute({sqlText: "TRUNCATE TABLE SENSOR_LAB.GOLD.DAILY_STATS"});

        // 時間帯別集計: Silver のビューから HOURLY_STATS へ
        snowflake.execute({sqlText: `
            INSERT INTO SENSOR_LAB.GOLD.HOURLY_STATS
            SELECT location, recorded_date, recorded_hour,
                COUNT(DISTINCT sensor_id),      -- ユニークセンサー数
                ROUND(AVG(temperature_c),2),    -- 平均気温
                MIN(temperature_c), MAX(temperature_c),
                ROUND(AVG(humidity_pct),2),     -- 平均湿度
                MIN(humidity_pct), MAX(humidity_pct),
                SUM(CASE WHEN is_anomaly THEN 1 ELSE 0 END),  -- 異常件数
                CURRENT_TIMESTAMP()
            FROM SENSOR_LAB.SILVER.V_SENSOR_VALID  -- NULLや異常値を除いたビューを使用
            GROUP BY location, recorded_date, recorded_hour
        `});

        // 日次集計: HOURLY_STATS から DAILY_STATS へ（2重計算防止のため）
        snowflake.execute({sqlText: `
            INSERT INTO SENSOR_LAB.GOLD.DAILY_STATS
            SELECT location, stat_date,
                SUM(sensor_count), ROUND(AVG(avg_temp),2),
                MIN(min_temp), MAX(max_temp),
                ROUND(AVG(avg_humidity),2), MIN(min_humidity), MAX(max_humidity),
                SUM(anomaly_count), CURRENT_TIMESTAMP()
            FROM SENSOR_LAB.GOLD.HOURLY_STATS
            GROUP BY location, stat_date
        `});

        return "Gold aggregation completed.";
    } catch(err) {
        return "ERROR: " + err.message;
    }
$$;
```

## 6-4 3層まとめて実行するマスタープロシージャ

> 💡 **マスタープロシージャとは？**
> 複数のプロシージャを順番に呼び出す「統合エントリーポイント」です。
> これにより外部からは `SP_FULL_PIPELINE()` の1コールだけで
> Bronze→Silver→Goldの全処理が実行されます。
>
> **やらないと？** 3つのプロシージャを毎回順番通りに手動で呼ぶ必要があります。
> **やると？** 次のChapterのTaskに `SP_FULL_PIPELINE` を1つ登録するだけで
> 全パイプラインの定期実行が設定できます。

```sql
CREATE OR REPLACE PROCEDURE SENSOR_LAB.BRONZE.SP_FULL_PIPELINE()
RETURNS VARCHAR
LANGUAGE JAVASCRIPT
EXECUTE AS CALLER
AS $$
    var results = [];  // 各ステップの結果メッセージを収集する配列

    // 実行するプロシージャを配列で定義（順番が重要: Bronze → Silver → Gold）
    var procs = [
        "CALL SENSOR_LAB.BRONZE.SP_LOAD_FROM_STAGE('BRONZE_STAGE', '.*sensor_.*\\\\.csv')",
        "CALL SENSOR_LAB.SILVER.SP_TRANSFORM_TO_SILVER()",
        "CALL SENSOR_LAB.GOLD.SP_AGGREGATE_TO_GOLD()"
    ];

    // 順番に実行（1つでもエラーになれば break で中断）
    for (var i = 0; i < procs.length; i++) {
        try {
            var res = snowflake.execute({sqlText: procs[i]});
            res.next();                             // 結果セットの最初の行に移動
            results.push(res.getColumnValue(1));    // 各プロシージャの戻り値を収集
        } catch(err) {
            results.push("STEP " + i + " ERROR: " + err.message);
            break;  // エラーが出たら後続ステップを実行せず終了
        }
    }
    return results.join(" | ");  // 全ステップの結果をパイプ区切りで返す
$$;

-- 全パイプライン実行テスト（Bronze→Silver→Goldが1コールで完結）
CALL SENSOR_LAB.BRONZE.SP_FULL_PIPELINE();
```
